# Porto Live Buses

A web app that shows the live position of the STCP buses in Porto on a map. The positions come from the Porto Digital FIWARE context broker. You can filter the buses by **route**, **zone** and **bus**.

Data source (NGSI v2):

```
https://broker.fiware.urbanplatform.portodigital.pt/v2/entities?q=vehicleType==bus&limit=1000
```

## Running it

You need Node.js 20 or later.

```bash
npm install
npm run dev        # http://localhost:5173
```

Other scripts:

| Command            | What it does                                                    |
| ------------------ | --------------------------------------------------------------- |
| `npm run build`    | Type-checks the code and builds a static site into `dist/`      |
| `npm run preview`  | Serves the production build locally                             |
| `npm test`         | Runs the unit tests (Vitest)                                    |
| `npm run zones`    | Regenerates `src/data/zones.json` from geoapi.pt (rarely needed) |

The broker sends `Access-Control-Allow-Origin: *`, so the browser calls it directly. No proxy or backend is needed, and the `dist/` folder can be hosted on any static host. To use a different endpoint, set `VITE_BUSES_URL` in a `.env` file.

## Features

- **Live map.** Each bus is a pin in its route's colour, labelled with the route number. An arrow shows its heading.
  - Stopped buses are drawn hollow.
  - Reports older than 5 minutes are faded.
  - When new data arrives, the pins glide to their new positions and leave a short trail.
- **Auto-refresh** every 10, 20, 30 or 60 seconds, or paused. Polling also stops while the tab is in the background.
- **Route filter.** Route chips are grouped by STCP series (200s, 300s … 900s, night lines). Each chip shows its bus count. You can pick single routes or a whole series, and there's a search box for routes.
- **Zone filter:**
  - **Municipalities and parishes (freguesias)** of the six municipalities STCP serves: Porto, Matosinhos, Maia, Vila Nova de Gaia, Gondomar and Valongo. You can tick them in the list or click a parish on the map. The boundaries can be drawn on the map.
  - **Custom area.** Click the map to place a circle, drag it to move it, and change its radius with the slider.
- **Bus filters:**
  - free-text search by bus number or route, with several values allowed (e.g. `3459, 205`)
  - direction of travel
  - moving or stopped
  - how recent the last report is
- **Faceted counts.** Each option shows how many buses you would get with the other filters still applied.
- **Bus list and details card.** Click a bus to see its speed, heading, zone, trip and last report. From the card you can *follow* the bus or show *only its route*.
- Filters and preferences are kept in `localStorage`.
- Light and dark themes follow the system setting, and the layout works on mobile with an off-canvas filter panel.

## Project structure

```
src/
  api/fiware.ts       Fetches the bus entities (with paging) and turns them into Bus objects
  domain/bus.ts       Bus model and helpers (moving / age)
  domain/filters.ts   Filter state, filtering, facet counts, persistence (pure, unit-tested)
  domain/routes.ts    Route grouping, ordering and colours
  domain/zones.ts     Point-in-polygon lookup of municipality / parish
  map/busLayer.ts     Leaflet markers and trails
  map/zoneLayer.ts    Municipality and parish polygons
  map/areaTool.ts     Custom circular area
  ui/panel.ts         Renders the sidebar lists and the bus card
  ui/format.ts        Formatting helpers and HTML escaping
  main.ts             Wires state, map, sidebar and the refresh loop together
  data/zones.json     Simplified boundaries (generated by scripts/build-zones.mjs)
tests/                Vitest unit tests
```

## How the data is read

Each `Vehicle` entity carries STCP annotations such as `stcp:route:200`, `stcp:sentido:0` and `stcp:nr_viagem:…`. These are parsed into the route, direction and trip.

- If the annotations are missing, the route is taken from the entity name (`STCP 200 3459`).
- Speed is in km/h. A bus counts as *moving* at 2 km/h or more, which absorbs GPS jitter at stops.
- Zones are found by testing each bus position against the parish polygons.
