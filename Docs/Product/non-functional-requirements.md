# Non-Functional Requirements

> LABDSOF 2026/27 · Sprint A · Assignment §6 (Common Technical Requirements), §8.3–8.5 and §9 (*Requirements and quality attributes*)
> **Status (24 October 2026):** one list of the quality attributes already spread across the repository, for the Sprint A deck (meeting with the professor of 22 October 2026, *Presentation contents*; #137). **No new decisions:** every target comes from the linked source. **[PROPOSED]** targets are not agreed by the team yet; **[PENDING]** means no target exists yet, with the owner from the [architecture decisions guide](../Technical/architecture-decisions-guide.md) (owners table); *(PR #52)* and *(PR #47)* mark values that are only in an open pull request ([#52](https://github.com/tomasoliveira21/LABDSOF/pull/52): resilience, #43; [#47](https://github.com/tomasoliveira21/LABDSOF/pull/47): identity and API gateway, #46) and change if the PR changes.
> Legend: see [`product-vision.md`](product-vision.md#legend).

Functional requirements (features and user stories) are in [`features.md`](features.md). This page lists how well Farol must do them: each requirement has a measurable target and the test, demo or metric that proves it. Categories follow the ISO/IEC 25010 quality characteristics; observability (assignment §6.7) and privacy (RGPD) are listed on their own because the assignment asks for them separately. The architecture drivers behind most of them are in [`architecture.md` §1](../Technical/architecture.md#1-architecture-drivers).

## 3. Open points

- **Confirm the [PROPOSED] targets** of SC1, SC2, SC4, SC6 and SC11: only SC3 (30 s) was set by the team ([`product-vision.md` §5](product-vision.md#5-measurable-success-criteria)).
- **Merge PR #52 and PR #47.** Until then their values (NFR-05, NFR-08, NFR-10, NFR-11, NFR-15, NFR-17, NFR-18) are proposals; update this page if they change.
- **On-time triage target differs between two proposals:** ≥ 90 % on-time coverage ([ADR-005](../Technical/adr/0005-ai-triage-provider-and-evaluation.md)) and ≥ 95 % within 30 s over 1 h ([observability research](../Research/architecture-investigation/observability.md#slis-and-proposed-slos-i2)). NFR-03 uses the second; Tomás (K1, I2) to align.
- **Outbox alert threshold differs:** oldest pending row > 30 s for 2 min (observability research) and > 60 s (PR #52, `architecture.md` §6). To align when PR #52 is merged (Tiago, Tomás).
- **Polling every 10 s and SC6 ≤ 10 s** *(PR #52, J3)*: the worst case is one interval plus the server time, so it can pass 10 s. Either the interval or the SC6 target needs adjusting.
- **Availability and recovery targets assume a deployed service;** delivery is local only ([ADR-011](../Technical/adr/0011-deployment-and-infrastructure.md)). NFR-12 and NFR-13 are reported from local runs and drills, with no cloud HA claimed.
- **No target yet** for accessibility (NFR-25, no owner), retention periods (NFR-19, D5 deferred) and the help-request rate limit (NFR-17, Guerra).
- **Weak-network mode (F11, SC10)** is a Could: not listed as an NFR; added only if F11 is built.
